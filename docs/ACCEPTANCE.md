# USTC Play 第一阶段验收标准

验收环境：iPhone 尺寸浏览器（建议 375 × 812 与 390 × 844）及桌面 Chromium。验收前清除站点数据一次，随后按每项步骤检查。除明确标识为模拟的内容外，不假定网络或其他设备存在。

## A. 基础与数据边界

| 编号 | 操作 | 可验证通过条件 |
| --- | --- | --- |
| A1 | 首次打开应用 | 默认进入首页，中文 UI 完整，底部有首页、发现、我的状态、好友、我的五项导航。 |
| A2 | 阅读首页提示、球场详情、个人页和 README | 至少在产品 UI 的两个位置与 README 中明确：这是单设备原型，好友/热度/人数为模拟或仅本机保存，不跨设备同步。 |
| A3 | 刷新页面 | 已保存的收藏、关注、昵称、隐私、状态和上报仍存在；清除站点数据后恢复初始数据。 |
| A4 | 检查球场信息 | “最近 N 人上报”“正在打球”“准备前往”“今晚可能”同时可见且语义区分清楚；不能把最近上报人数显示成场上人数。 |

## B. 首页与发现

| 编号 | 操作 | 可验证通过条件 |
| --- | --- | --- |
| B1 | 首页切换篮球/足球 | 列表只显示对应运动项目；切换不改变用户已有收藏。 |
| B2 | 点“查看全部/只看收藏” | 文字与列表模式同步切换；无收藏时有可用的空状态入口。 |
| B3 | 点星标 | 收藏状态立即切换，列表/我的页数量同步，并在刷新后保持。 |
| B4 | 进入发现页并切换项目 | 显示对应项目的全部模拟场地及推荐场地；点击卡片或推荐可进入正确详情。 |

## C. 球场详情与上报

| 编号 | 操作 | 可验证通过条件 |
| --- | --- | --- |
| C1 | 打开任一球场 | 显示名称、项目、位置、步行时间、设施、热度、最近上报信息及三类人数。 |
| C2 | 不选热度直接发布 | 不保存记录，并出现“请先选择球场热度”一类的明确提示。 |
| C3 | 选择任一五级热度并任选一项现场说明，再发布 | 出现成功反馈；再次进入该球场可看到本机刚刚上报的热度。实现更新后还应可确认现场说明与时间。 |
| C4 | 对比上报前后人数 | 一次本机热度上报不得伪装为新增真实场上人数；若总数未聚合，应保持不变并有本机/模拟说明。 |
| C5 | 点详情星标或返回 | 星标状态可保存；返回后停留在对应页面且没有误触发上报。 |

## D. 我的运动状态与隐私

| 编号 | 操作 | 可验证通过条件 |
| --- | --- | --- |
| D1 | 依次选择六种状态 | 每项都有明确标签、说明与可辨别的选中状态，包含“隐身”。 |
| D2 | 切换篮球/足球 | 球场下拉列表只显示对应项目，并能选择“暂不选择球场”。 |
| D3 | 选状态、球场、有效期后更新 | 有成功反馈；“我的”页立即显示状态、运动类型和所选球场，刷新后仍在。 |
| D4 | 等待有效期结束或用很短测试时长验证 | 过期后个人页不再将状态显示为有效，且文案能区分“已过期”和“已隐藏”。 |
| D5 | 关闭“向好友展示运动状态” | 开关状态立即变化并刷新后保持；个人页明确显示状态已对好友隐藏。本机原型不声称已影响其他真实用户。 |

## E. 好友

| 编号 | 操作 | 可验证通过条件 |
| --- | --- | --- |
| E1 | 搜索昵称或 ID | 仅显示匹配的模拟好友；清空后恢复；无匹配时显示空状态。 |
| E2 | 切换“全部/我关注的/关注我” | 筛选结果符合当前模拟关系，且“关注我”明确是演示数据或真实同步功能尚未启用。 |
| E3 | 点击关注/取消关注 | 按钮、关注筛选和刷新后的状态一致；操作有清晰反馈。 |
| E4 | 查看隐身好友 | 不展示其球场或运动计划细节。 |

## F. 移动端、视觉与可访问性

| 编号 | 操作 | 可验证通过条件 |
| --- | --- | --- |
| F1 | 以 375 × 812 和 390 × 844 打开并滚动各页 | 无横向滚动、文字重叠或底部导航遮住主操作按钮；底部安全区留白正确。 |
| F2 | 查看主流程 | 蓝色主操作、绿色积极状态、白色卡片、圆角和柔和阴影保持一致；热度不只依赖颜色表达。 |
| F3 | 使用键盘 Tab（桌面）或辅助功能焦点 | 导航、星标、卡片入口、表单和开关均可获得焦点并有可见焦点样式。 |
| F4 | 点击/轻触关键控件 | 常用控件的可点击区域约为 44 × 44 px；快速重复点击不应产生重复报错或布局跳动。 |

## G. 工程与发布门槛

| 编号 | 操作 | 可验证通过条件 |
| --- | --- | --- |
| G1 | 在规范项目根目录执行 `npm run check` 与 `npm run build` | 两个命令退出码均为 0；构建产物生成成功。 |
| G2 | 检查提交内容 | `.gitignore` 排除 `node_modules`、`dist`、`.env*`、本地密钥/令牌文件；不提交构建产物或压缩部署包，除非有明确理由。 |
| G3 | GitHub Pages 构建 | GitHub Actions 成功，Vite `base` 与仓库 Pages 路径匹配，静态资源不出现 404。 |
| G4 | 真实外网验证 | 至少从部署构建环境以外的浏览器访问公开地址、刷新首页并执行一次本机交互。仅有构建环境 HTTP 200 不构成通过。 |

## 当前验收结论（代码审查）

- 基础核心流程可演示，B1–B4、C1–C3、D1–D3、E1–E4的主要 UI 与本机状态逻辑已具备。
- 尚未完成 G3–G4；目前也未证实公开链接在用户网络可用。
- A4、C4、D4、D5、E2、F3 需要按 `PRODUCT_SPEC.md` 的产品意见补强或用明确的模拟文案收口后再验收。
